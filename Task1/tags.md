# Схема тегирования

### Основные категории тегов
* Тип данных:
  * PII — персональные данные (ФИО, паспорт, телефон).
  * MED — медицинские данные (диагноз, анализы, назначения).
  * FIN — финансовые данные (чеки, реквизиты).
  * EMP — данные сотрудников.
  * SYS — служебная/техническая информация.
* Уровень чувствительности:
  * LOW — некритичные (рабочие заметки).
  * MEDIUM — внутренние данные (отчеты без персонализации).
  * HIGH — конфиденциальные данные (паспорт, мед. диагноз).
  * CRITICAL — строго конфиденциальные (медицинские истории болезни, платежные реквизиты).
* Метод защиты:
  * ENC — требуется шифрование.
  * MASK — требуется маскирование (например, отображение части номера паспорта).
  * ANON — требуется обезличивание.
  * AUDIT — требуется аудит доступа.

### Пример тегов для сущностей
* Пациент (ФИО, паспорт, телефон):
  * PII
  * HIGH
  * ENC
  * MASK
* Медицинский анализ:
  * MED
  * CRITICAL
  * ENC
  * ANON
  * AUDIT
* Финансовая транзакция:
  * FIN
  * CRITICAL
  * ENC
  * MASK
  * AUDIT
* Отчет для руководства:
  * SYS
  * MEDIUM
  * ANON

### Инструменты для тегирования:
* В БД — отдельная таблица метаданных с колонкой tags, связанной с каждой сущностью.
* В файловом хранилище — использование метаданных файлов (например, S3 Object Tags, MinIO Metadata).
* В e-mail и документах — Microsoft Azure Information Protection.

### Автоматическое присвоение тегов:
* При вводе данных — правила классификации (например, регулярки для паспортов, телефонов, медицинских кодов).
* При загрузке файлов — сканирование содержимого (DLP/Regex/NLP).
* При передаче через API — middleware добавляет теги в метаданные.

###	Использование тегов:
* При чтении данных → проверка тегов → применение правил (шифровать, маскировать, логировать).
* При экспорте данных → автоматическое обезличивание, если тег ANON.
* В отчетах → скрывать поля с тегом MASK.
