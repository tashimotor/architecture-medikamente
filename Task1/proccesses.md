## Процесс: Запись пациента на приём
Как сейчас: данные пациента заносятся вручную в Excel → подтверждения идут через Outlook.
Проблемы:
* Excel и Outlook не являются СЗД (системами защиты данных).
* Нет централизованного контроля доступа.
* Нет шифрования на уровне хранения.

ФЗ-152:
* Ст. 19: оператор обязан принимать меры по защите ПДн от неправомерного доступа.
* Ст. 5: минимизация обработки ПДн — хранение в Excel противоречит принципу.

Архитектурные практики:
* Использовать защищённую CRM/EMR (электронную медсистему).
* Шифрование данных в БД (AES-256).
* RBAC/ABAC для разграничения доступа.
* Двухфакторная аутентификация для сотрудников.

## Процесс: Хранение и обмен медицинских документов
Как сейчас: сканы и результаты анализов хранятся на файловом сервере, рассылаются через Outlook, ссылки на документы фиксируются в Excel.

Проблемы:
* Документы содержат чувствительные ПДн (медицинская тайна).
* Нет журналирования доступа и контроля за копированием.
* Пересылка по e-mail без шифрования нарушает принцип «целостность и конфиденциальность».

ФЗ-152 + Приказ ФСТЭК/ФСБ:
* Ст. 10: обработка спецкатегории данных (состояние здоровья) требует повышенной защиты.
* Ст. 19: обязанность по предотвращению утечки (в т.ч. через e-mail).
* Требования по криптографической защите (ГОСТ, СКЗИ).

Архитектурные практики:
* Использовать ECM/DMS систему с криптографическим хранилищем.
* Шифрование каналов передачи (TLS 1.3, ГОСТ VPN).
* DLP-системы для контроля рассылок и вложений.
* Логирование всех операций доступа (SIEM).

## Процесс: Финансовый учёт и отчётность
Как сейчас: приём оплаты через кассу → данные попадают в 1С → отчёты формируются вручную в Excel → отправляются по Outlook руководству.
Проблемы:
* Дублирование финансовых данных (Excel + 1С).
* Отправка отчётов по почте без защиты.
* Нет разграничения между операционным и управленческим доступом.

ФЗ-152 + 402-ФЗ (бухгалтерский учет):
* Ст. 18 ФЗ-152: защита финансовых данных, если они связаны с персональными (например, ФИО пациента в чеке).
* Требование вести учёт в защищённых системах (1С можно сертифицировать, Excel — нет).

Архитектурные практики:
* Отчётность формировать внутри 1С (или BI-системы) без промежуточных Excel.
* Использовать защищённые каналы передачи отчётов (SFTP, защищённые API).
* RBAC для бухгалтеров и руководства.
* Журналирование всех действий в финансовых системах.
